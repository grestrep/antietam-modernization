# The exe patch, in code

> **Historical.** This is the binary patch used during the investigation. The released `ddraw.dll` does the same at load time by redirecting the exe's `GlobalFree` import, so no exe is patched or distributed (see [ddraw-dll.md](ddraw-dll.md) §3.0). The code below still shows exactly what the fix does.

Applies to `SMAntietam1210.exe` (from v12.10 `Antietam.exe`, 806,912 bytes). The v9.84 `SMAntietam.exe` patch is identical, only at different addresses.
Generated by `tools/patch/patch_globalfree_auto.py`. Disassembly below is in Intel syntax.

## 1. The bug (example from the v9.84 palette routine at 0x472BA0)
```asm
push 404h
call 0049AF6E            ; malloc(0x404)       <- C runtime heap
mov  esi, eax
...                      ; fill a LOGPALETTE in [esi]
push esi
call [CreatePalette]
push esi
call [GlobalFree]        ; GlobalFree(esi)     <- wrong: frees CRT memory with the Win32 global heap API
```
The exe imports `GlobalFree` but **never** `GlobalAlloc`, so every `GlobalFree` call in the game frees CRT-heap memory. Windows 9x tolerated it. On Windows 11 it corrupts the heap and crashes about 30 s in.

## 2. New code: a GlobalFree-compatible stub that calls the game's own `free()`
Placed in unused zero padding at the end of `.text`, at **0x4AF370** (22 bytes). `.text` VirtualSize was raised from `0xAE352` to `0xAE3B0` so it is mapped.
```asm
; HGLOBAL __stdcall GlobalFree_fix(void* p)
4AF370  mov  eax, [esp+4]      ; 8B 44 24 04   p
4AF374  test eax, eax          ; 85 C0
4AF376  je   4AF383            ; 74 0B         free(NULL) -> nothing to do
4AF378  push eax               ; 50
4AF379  call 004A4D33          ; E8 xx xx xx xx   the game's statically linked MSVC6 free()
4AF37E  add  esp, 4            ; 83 C4 04      free() is cdecl
4AF381  xor  eax, eax          ; 31 C0         GlobalFree returns NULL on success
4AF383  ret  4                 ; C2 04 00      stdcall, 1 argument (like GlobalFree)
```
The game's own `free()` at 0x4A4D33, unchanged (MSVC6 CRT with small-block-heap lookup):
```asm
4A4D33  push esi
4A4D34  mov  esi, [esp+8]
4A4D38  test esi, esi
4A4D3A  je   ...
4A4D3C  push 9
4A4D3E  call _lock              ; heap lock
4A4D44  call __sbh_find_block   ; small-block heap?  -> __sbh_free_block
...                             ; otherwise HeapFree(_crtheap, 0, p)
```

## 3. Redirecting every GlobalFree reference (68 sites)
Each patched instruction keeps its original length (6 bytes), so no other code moves.

**a) 59 direct calls**: `call [GlobalFree]` → `call stub` + `nop`
```
before  0x405073:  FF 15 2C 01 4B 00     call dword ptr [004B012Ch]   ; GlobalFree
after   0x405073:  E8 F8 A2 0A 00        call 004AF370                ; stub
        0x405078:  90                    nop
```
**b) 7 register loads** (`mov ebp, [GlobalFree]`, later `call ebp`): the register now holds the stub address
```
before  0x4809B9:  8B 2D 2C 01 4B 00     mov ebp, dword ptr [004B012Ch]
after   0x4809B9:  BD 70 F3 4A 00        mov ebp, 004AF370h
        0x4809BE:  90                    nop
```
**c) 2 register loads into ebx**, the same idea:
```
before  0x481630:  8B 1D 2C 01 4B 00     mov ebx, dword ptr [004B012Ch]
after   0x481630:  BB 70 F3 4A 00        mov ebx, 004AF370h
        0x481635:  90                    nop
```
After patching, nothing in `.text` references the `GlobalFree` import slot (0x4B012C) any more. The script checks this.

## 4. The patcher (core of tools/patch/patch_globalfree_auto.py)
```python
stub = bytes.fromhex('8b44240485c0740b50') + b'\xe8' + struct.pack('<i', FREE - (STUB + 14)) \
     + bytes.fromhex('83c40431c0c20400')
d[s:s+22] = stub                                                    # write stub into code cave
struct.pack_into('<I', d, sh+8, new_vsize)                           # extend .text VirtualSize
for m in re.finditer(re.escape(b'\xff\x15' + slot), text):           # call [GlobalFree]
    d[p:p+6] = b'\xe8' + struct.pack('<i', STUB - (va(p) + 5)) + b'\x90'
for op, mov in ((b'\x8b\x2d', 0xbd), (b'\x8b\x1d', 0xbb), (b'\x8b\x35', 0xbe), (b'\x8b\x3d', 0xbf)):
    for m in re.finditer(re.escape(op + slot), text):                # mov reg, [GlobalFree]
        d[p:p+6] = bytes([mov]) + struct.pack('<I', STUB) + b'\x90'
assert text.count(slot) == 0                                         # nothing left unpatched
```
The `GlobalFree` slot, `free()` (found by its MSVC6 byte signature `56 8B 74 24 08 85 F6 74 ?? 6A 09 E8`) and the code cave are all auto-detected. The script stops if any of them is ambiguous.

## 5. Rename
`Antietam.exe` → `SMAntietam1210.exe`. This is not a code change: Windows' compatibility database applies the EmulateHeap shim by file name, and that shim crashes on Windows 11.
